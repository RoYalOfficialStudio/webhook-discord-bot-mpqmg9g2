# Soak test 2026-09-29 – long-session memory / handle growth

Tool: `roy_soak` (new, `apps/roy_soak/main.cpp`, shipped in the test kit).
Session content is **MOCK** (synthetic input signal, generated MIDI/beat); the engine, runtime,
recorder, undo, sandbox, exporter and session code are the real ones.

## What one cycle does (≈ 1 simulated minute of studio work)
1. 30 s playback with random seek and loop on/off
2. 10 s recording on an armed track → take added (one undo step), the previous take deleted (`DeleteTake`; its WAV stays in the project folder)
3. edits: add a MIDI track with an instrument + insert, delete the oldest extra track, groove change, master gain; 3× undo, 2× redo, graph rebuild
4. every 5th cycle: a sandboxed CLAP plugin (RoY TEST gain) inserted, 2 s audio, removed → a plugin host process starts and ends
5. every 10th cycle: 20-beat WAV export (then deleted) + session save

Measured after each cycle: RSS, open file descriptors, threads, undo-history bytes.
Verdict: linear fit through the second half of the RSS samples < 20 MB per simulated hour,
fds ≤ start + 4, threads ≤ start + 2, 0 failed operations.

Environment: Linux x86_64, GCC 13 RelWithDebInfo, 48 kHz / 256 samples, 3 worker threads, undo limit 200 steps.

## Run 1 – before the fix: **FAIL**
120 cycles = 2.0 simulated hours in 7.9 min (120 takes, 12 exports, 24 sandboxed plugin loads).

| Check | Second half start | End | Verdict |
|---|---|---|---|
| RSS | 293.8 MB | 412.4 MB | +118.1 MB per simulated hour → **FAIL** |
| fds | 4 | 4 | PASS |
| Threads | 5 | 5 | PASS |
| Undo memory | 28.4 MB | 35.6 MB | – |
| Failed operations | | 0 | PASS |

RSS grew ~2 MB per cycle = exactly one 10 s mono take at 48 kHz float.

**Root cause:** `ProjectRuntime` caches decoded audio (`assets_`, `derivedAssets_`) and never
released anything. Every recorded take, every deleted clip and every time-stretch/pitch variant
(e.g. each value while dragging a stretch slider) stayed in RAM until the project was closed.
In a real session with long takes (3 min stereo ≈ 69 MB each) this grows by gigabytes.

**Fix:** `ProjectRuntime::pruneAssetCache()` runs after every graph rebuild and drops data that
(a) only the cache still holds (not used by the audio graph, a processor or a caller) and
(b) is not referenced by the project (clips incl. raw/tuned versions, takes, sample rows) and
(c) was not injected without a file (`addLoadedAsset`). Stretch variants referenced by a clip stay
(a muted stretched clip must not be re-stretched on unmute). Undo that brings a take/clip back
simply reloads it from its file. Test: `takes/runtime asset cache: …` (pinned / used / muted
variants stay, deleted takes and old variants go, restored take plays again).

## Run 2 – after the cache fix: **PASS**
| Check | Second half start | End | Verdict |
|---|---|---|---|
| RSS | 174.2 MB | 135.7 MB | −4.1 MB per simulated hour → **PASS** |
| fds | 4 | 4 | PASS |
| Threads | 5 | 5 | PASS |
| Undo memory | 28.4 MB | 35.6 MB | – |
| Failed operations | | 0 | PASS |

RSS stays in a 127–179 MB band (glibc arenas grow/shrink around the export cycles); no trend.

## Second finding – undo history size
Every undo step stored the whole project twice (before + after), limited only by the step count
(500). For a large project (2 MB model) that is up to 2 GB. The history still grew slowly in
the soak because the project model grows (one asset entry per recorded take).

**Fix:** consecutive steps now share the common state (step N "after" = step N+1 "before" →
about half the memory), and a byte budget (default 512 MB, `setMemoryLimit`) drops the oldest
steps; the newest step always stays. Test: `gmb02/undo history: …` (3000-note project:
20 steps = 21 stored states, budget respected, undo/redo exact).

## Run 3 – with both fixes (final): **PASS**
120 cycles = 2.0 simulated hours in 7.7 min (120 takes, 12 exports, 24 sandboxed plugin loads).
Also includes the GUI waveform-peak cache pruning (`WaveformStore::retainOnly`, same reference rule).

| Check | Run 1 (before) | Run 3 (final) |
|---|---|---|
| RSS trend (2nd half) | +118.1 MB / sim. hour – FAIL | −12.7 MB / sim. hour – PASS |
| RSS at end | 412.4 MB | 108.1 MB (band 107–153 MB) |
| Undo history at end (200 steps) | 35.6 MB | 18.1 MB |
| fds / threads | 4 / 5 flat | 4 / 5 flat |
| Failed operations | 0 | 0 |

Raw samples: `SOAK_2026-09-29_final_raw.md`.

## Limits of this test
* Linux only; Windows repeat: TEST_REPORTS/WINDOWS_NATIVE_TEST_PLAN.md 9.1 (`roy_soak.exe`, in the test kit).
* Accelerated: 2 simulated hours of *operations*, not 2 hours of wall-clock time (timer/driver
  effects of a real multi-hour session need test 9.2 on real hardware).
* GUI not exercised by `roy_soak` (the waveform-cache fix is covered by a unit test).
